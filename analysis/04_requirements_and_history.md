## 1. 專案背景與時間軸

### 1.1 背景

- 客戶：鶴見製作所股份有限公司（Tsurumi Pump Taiwan，桃園八德台灣工場）。賣方：金泰科技（ANSER）。2012-05-02 簽訂「SP2000 噴印系統」買賣合約。約定 2012-07-15 前交貨安裝、2012-09-15 前驗收，驗收後保固 12 個月；輸送帶機構由鶴見負責（2012-06-15 前完成）。〔鶴見/軟體需求規格書/其它/鶴見製作所-1.doc〕
- 目的：把泵浦外箱（紙箱）上原本的印刷或貼標，改成在產線上用噴墨直接噴印型式、規格、製番條碼、商品碼與機番條碼。軟體要把「輸入檔（Excel）」轉成噴印資料，由作業員選定一筆後送到噴印站噴印，並記錄產量。〔鶴見/軟體需求規格書/Tsurumi printing Console software requirements specifications_0516_CN.xls，sheet「一.说明」〕
- 系統名稱：鶴見噴印控制台（英文 Tpcsrs，執行檔 `HeJianPrintingConsole.exe`，「鶴見」簡體拼音 HeJian）。
- 共有三代軟體：
  1. **C#/.NET 4 版（2012-06 至 2013-09，V1.1.1.5 → 2.1.26）**：廈門研發開發。架構是 SP2000 ADT 通道 + Printing PRO + SQL Server 2005 Express。〔鶴見/8502030366 鶴見噴印控制臺使用手册 (V1.1)_客戶使用.doc〕〔analysis/decompiled_dotnet〕
  2. **C++Builder 6 改寫版（2015-11 至 2016-05，hejian 2.1.0.2 → 2.1.2.6，另有 20160530 版）**：仍走 ADT（`aimdtl.dll`），資料庫改名為 `hejian`，設定檔是 `hejian.xml`（INI 格式）。〔鶴見/hejian_2.1.*〕〔analysis/delphi_hejian/version_history_raw.txt〕
  3. **本次重寫**：改用 NexGen X1/SPH，透過 TCP 直接控制（協定見 `analysis/01_X1_protocol.md`），不再使用 ADT 與 Printing PRO，卡匣改為 1 吋。
- 2021-02-25 的現場截圖顯示，C++Builder 版仍在 Win10 電腦上跑；客戶端的 ERP 匯出檔名為「印刷明細一覧表」，內含「產品編號（台灣）」與「產品編號（紙箱）」（例如 `17401158`）。〔鶴見/UI/管理平台.jpg、鶴見/UI/訊息.jpg〕

### 2.2 輸送帶與紙箱

- 輸送帶由鶴見委外廠商製作。紙箱直立行進，兩側噴頭同時噴兩個相對的側面。3D 示意圖顯示：門型框架、兩側噴頭架、2 個 SP2000 控制箱。〔0516_CN.xls 內嵌圖〕
- 每個側面的噴印範圍跨兩個面：長面（L）放「正嘜」，相鄰的短面（W）放「側嘜」，中間是紙箱合縫面（パッキングケース合せ面）。**表面從左往右噴，裏面方向相反**。〔0516_CN.xls 內嵌「印字位置」圖；20120723_DB案.xls「印字位置②～⑥」〕
- 速度：驗收時每分鐘 7~8 箱（00472 箱 8 箱/分），廠商處曾測到 10 箱/分。每箱間隔設 2 秒。〔鶴見20120723.txt、鶴見20120810.txt〕
- 尺寸範圍：最寬紙箱 75 cm、最窄 55 cm；高度可到 90 cm。L+W 的噴印長度可達約 80~90 cm，曾因此噴不完（日文資料）。〔鶴見20120723.txt〕
- 輸送帶機構問題：原本兩邊各一個馬達夾送，兩邊速度不同造成打滑錯位，後改成「單邊馬達 + 另一邊可調鬆緊滾輪」，誤差小於 1 mm。噴頭與紙箱太近會擦糊條碼，所以加裝單噴頭前後微調機構；01173 箱常被噴頭卡住。〔鶴見問題報告.pptx；鶴見20130604出差.doc〕

## 3. 功能需求

### 3.1 作業流程（規格書 0516）

1. 先在「系統設定」設定軟體、噴印站與噴頭。
2. 在「噴印資料管理」與「紙箱規格管理」匯入資料。
3. 在主畫面輸入 **Key code、製番、箱數、機番** 四欄後，「讀取資料」按鈕才能按。
4. 按「讀取資料」後，用 Key code **模糊查詢**，進入「噴印資料選擇」視窗，雙擊選一筆。
5. 用預覽檢查（依 Printing PRO 模板呈現），確認後開始噴印。
6. 現場檢查噴印內容與位置；位置不對就停機，到紙箱規格調整延遲。
7. 印到設定箱數就自動停止，並寫入生產紀錄。
〔0516_CN.xls「一.说明」〕

- 客戶實際作業方式：每次換紙箱規格，先用測試箱噴第一筆，正常後才接著噴；**每噴一箱都確認一次**。〔鶴見2013問題總結與歷史紀錄.xls〕
- 從生產紀錄看，現場常常「印 1 箱 → 停 → 再印」，也會在批次中途停機、修改箱號後重啟。〔0305噴印紀錄.xls、20140401_2.xls、20150212-1169.xls〕

### 3.3 資料匯入

- 格式：最早規定 Excel 2003（.xls），每筆一列，A、B 欄（Key code、CASE-No）不可空白。C++Builder 版從 2.1.1.4 起也支援 .xlsx，並改用 `model\Excel*.xlsx` 範本匯出。〔0516_CN.xls「三.输入档案格式」；delphi version_history（2.1.1.4、2.1.1.14）〕
- 匯入規則：
  - 規格書寫「匯入前清除全部舊資料，並先詢問」。後來改成「資料已存在，是否覆蓋？」。
  - 要判斷檔案格式；選錯檔案（例如把 CartonSize.xls 當成 PrintData 匯入）要明確提示。
  - 匯出必須是全部資料，不是目前畫面上顯示的那些。
  〔0516_CN.xls；1.1.1.7 測試報告；1.1.4 測試報告；TWlanguage.ini DataHaveCZIsClear〕
- 每個欄位都有最大長度，可在系統設定中調整，並套用到輸入框；超長時要提示並標紅。〔2.1.8 測試報告；軟體修改要求1008.xls 問題九〕
- 已知資料問題：
  - CASE-No 被 Excel 當成數字，前導 0 消失（例如 `715.0`、`0715`）。〔鶴見/printdata/1229cartonsize.xls；20140513.xls〕
  - 有幾筆紙箱的「表面印字開始」大於「終了」（01160、01163、01172、01173，例如 770→170），需要釐清這些數值的語意。〔20140513.xls〕
  - 2.1.2.3 起會檢查「表面/裏面印字終了 不可大於 L+W」。〔TWlanguage.ini CartonOutSideDYLW〕
- 匯入元件依賴環境：C++Builder 版透過 OLEDB Jet/ACE 讀 Excel，現場多次出現「找不到提供者」「外部資料表不是預期的格式」「EAccessViolation」。〔hejian_2.1.1.10~2.1.1.15/loginfo/*.log〕

### 3.4 紙箱規格表（CartonSize）的語意

圖示來源：0516_CN.xls 與 20120723_DB案.xls 的「印字位置②～⑥」。

| 編號 | 欄位 | 意義（單位 mm） |
|---|---|---|
| ① | CASE-No | 紙箱編號，與 PrintData 的 CASE-No 對應 |
| — | Carton size-L / W / H | 紙箱長、寬、高 |
| ② | 印字高度 | 從紙箱底部到噴印區域上端的高度 |
| ③ | 表面印字開始 | 表面：從紙箱左端到開始噴印的位置 |
| ④ | 表面印字終了 | 表面：從紙箱左端到噴印結束的位置（跨過合縫面，到短面右端） |
| ⑤ | 裏面印字開始 | 裏面：從紙箱端點到開始噴印的位置（裏面噴印方向相反） |
| ⑥ | 裏面印字終了 | 裏面：噴印結束的位置 |
| （規格書有、實際檔案沒有） | MsgName | 這個紙箱對應的模板名稱 |

- 正嘜靠左、側嘜靠右。正嘜與側嘜之間的空白，會隨紙箱與資料不同而改變。〔0516_CN.xls「一.说明」R76-77〕
- 起印位置是用**延遲補償**做出來的，詳見下方的合成公式。〔合成模板计算方法.doc〕

**模板合成演算法（舊系統，重寫時要重新實作或替換）**〔鶴見/合成模板计算方法.doc；log 2013188.Log〕

- 表面寬度 W面 = 表面印字終了 − 表面印字開始。
- 間隙 = W面 − 正嘜模板寬 − 側嘜模板寬。
- 側嘜每個物件的 X 座標 = 正嘜寬 + 間隙 + 原 X。
- 整體模板：裏面物件的 Y 座標 = 8 × 150 + 原 Y（表面佔 8 個 0.5 吋噴頭）。
- 噴頭 1、2 的延遲 = 超級設定的延遲 + (表面開始 / DPI) × 25.4。
  - 原文這一行寫的是「里面開始位置」，從上下文看應該是筆誤。
- 噴頭 3、4 的延遲 = 超級設定的延遲 + (裏面開始 / DPI) × 25.4 + 補償2。
  - 補償2 只在表面寬度大於裏面寬度時才加：補償2 = ((表面寬 − 裏面寬) / DPI) × 25.4。
  - 原因是裏面的噴印方向相反。
- 實測值：WidthDPI 370 時，Msg1 寬 2992 點、Msg2 寬 3200 點，算出間隙約 1747 點。〔2013188.Log〕

**側嘜（短面，靠右對齊）**

| 內容 | 尺寸 |
|---|---|
| MODEL_value（大字） | 21×140 mm |
| PLACE（例如 `MADE BY TSURUMI TAIWAN`） | 7×86 mm |

**字型**
- Arial：ModelValueFront 140、ModelValueSide 280/255/150、Place 80→60/70。〔Config.xml；hejian.xml 各版〕
- VOLTAGE_unit 與 Hz_value 的間距設定 `SpaceBtVoltageHzValue=5`。〔Config.xml〕
- 日文用 MS-Gothic，`φ` 用 Gulim。〔Ø字體/MS-Gothic.zip；字體/gulim；軟體修改要求1016.xls〕

**客戶後來追加的版面要求**〔軟體修改要求1008.xls；1016.xls；サンプル評価結果_20121011.pdf〕
- PLACE 的字高要和正嘜的 CODE_value 一樣。
- 側嘜的數值要靠右，不能靠左。
- 預覽與實際都要從設定值（例如 40 mm）開始，不能多出系統留邊（實測多約 2 mm）。
- 冒號在預覽中不能消失。
- 匯出時各欄位的字型不能全部被改成 Arial。
- 全部紙箱的機番字高要統一成 01158 箱的尺寸。
- 內側摺蓋上的條碼希望不要印。

**機種差異**
- LSP 系列紙箱（00472/00473/01050/01051）只在紙箱下部噴製番、CODE、品目№、機番與條碼，印字高度約 170 mm。這種情況下噴頭 1、3 沒有資料，舊版曾因此算錯（2.1.15 修正）。〔Re FW 依頼／LSPパッキングケースTEST印字.eml；鶴見20120925.xls〕
- MODEL_value 空白時，側嘜曾整段消失。〔鶴見20120723.txt〕
- DB 案中「専用」箱是預印專用箱，不需要噴印；另有「不明」分類。〔20120723_DB案.xls〕

**側嘜資料的產生方式（舊系統）**〔鶴見噴印控制臺2.1.15EN修改報告.doc〕
- 側嘜欄位是先把字串轉成圖片（BMP）再送出。
- 圖片寬度以模板中的圖片為基準，字串靠右；超出寬度的部分直接截斷。

### 3.6 條碼

- 兩個 Code128 條碼：(1) 製番；(2) 商品碼（CODE_value）+ 機番。〔20120220印字DB案(鶴見).xls ueda案 R13〕
- 日方要求：條碼必須可讀。要確認可讀性，讀不到時要重印。〔サンプル評価結果_20121011.pdf〕
- 2014-12 的「Barcode 偵錯」需求〔鶴見Barcode偵錯_V1.2.xls〕：
  - 用條碼讀取器讀正、反面條碼，並記錄每支讀取器讀到的內容。
  - 遇到以下狀況就**立即停止噴印並顯示原因**：
    1. 正反面資料不一致；
    2. 任一面讀不到；
    3. 下載的資料與實際噴出的不一致。
  - 【推論】C++Builder 版 2.1.1.17~2.1.2.6 有 `TMSComm`（序列埠元件），可能是為了這個需求；20160530 版把它拿掉了。〔version_history_raw.txt〕

### 3.7 箱數與機番（流水號）

- 箱數：輸入「起始箱數 / 最大箱數」。1.1.1.5 版起改為從 0 開始計。印到最大值就自動停止。〔使用手冊；鶴見1.1.1.5EN版修改報告.doc〕
- 機番：由前綴與數值組成。格式隨年代與機種變化：
  - `B-10643301`、`T-5579216`（2012~2014）
  - `PRW-9036095`
  - `14118193397`、`15470599156`（2014 起：2 位年碼 + 製番數字 + 3 位箱序）
  - 2021 年的畫面：前綴 `21` + 數值 `678569136` → `21678569136`
  - 數值部分每箱 +1（會進位）。〔各生產紀錄 xls；UI/管理平台.jpg〕
- 順序或逆序：客戶要求可以選 0→100 或 100→0（2.1.16）。逆序時，箱數與機番、生產紀錄的開始/結束機番曾對不上。〔軟體修改要求1008.xls 問題五；鶴見2.1.16EN版測試報告.xls〕
- **同一箱的正反兩面必須是同一個機番與條碼**。這是最常見的客訴，見 §5。
- C++Builder 版的檢查與提示：「噴印箱數超過最大值」「噴印箱數超過可用機番」「噴印機番不能小於箱數，是否清空箱數與機番？」「噴印完成，是否清空箱數與機番？」。〔TWlanguage.ini〕

### 3.8 紀錄與報表

- 規格書：生產紀錄存成 Excel，欄位為 Key code、製番、紙箱編號、開始噴印箱號、結束噴印箱號、實際噴印箱數、開始機番、結束機番、開始日期/時間、結束日期/時間。〔0516_CN.xls「四.输出档案格式」〕
- 一個批次的定義：從按「噴印」到按「停止」。C# 版另有明細表，**每頁（每箱）一筆**。〔鶴見1.1.1.5EN版修改報告.doc；ClsDataBase.cs〕
- 文字用語從「箱號」改成「箱數」。〔2.1.16 測試報告〕
- 系統日誌：C# 版寫入 `Log\*.Log` 與 DB 的 `tlog` 表；升級前要先清 `tlog`。C++Builder 版寫 `loginfo\yyyymmdd.log`，每箱一行「Printing Serial Number」；另有 ADT 通訊日誌（`imPrintData`、`DoSend pagesn` 等）。〔单文件升级.txt；20160122/loginfo2.5/20160122.log；20160122/logs/Log_COM*.log〕

### 5.1 根因整理

- **「跳號 / 正反面差 N 號」不只一個原因**，至少包括：
  - (a) 控制台內部緩衝計數的競態（#25）；
  - (b) 停機或重啟時，已送出但還沒噴的頁怎麼處理，以及操作員手改箱號（#27）；
  - (c) 兩側噴印站各自由電眼觸發，任何一側多觸發（誤觸、紙箱抖動）或漏觸發，就會讓兩面錯一頁（#29~#31）；
  - (d) 首箱資料還沒下載完（#13）；
  - (e) 斷線後重連（#14）。

  舊架構沒有「每一頁（每箱）兩面都噴到」的閉環確認，只能靠事後人工檢查。
- **「位置偏移」主要來自機構與訊號**：米輪、同步器打滑、接地、DPI 不對、卡匣偏移，以及延遲公式（負值、噴印站順序）。軟體的責任在於延遲計算要正確，參數要可追蹤、可驗證。

## 6. 重寫的必要條件與建議

### 6.1 必須保留的功能（客戶已習慣、合約或客訴要求）

1. 主流程：Key code 模糊查詢選資料 → 輸入製番、起始/最大箱數、機番（前綴 + 數值，可順序或逆序）→ 預覽 → 噴印 → 達最大箱數自動停止 → 寫入生產紀錄。
2. 資料管理：PrintData 與 CartonSize 都要能做 CRUD 與 Excel 匯入匯出（.xls 與 .xlsx 都要支援，CASE-No 以文字保存並保留前導 0），欄位最大長度可設定並驗證。
3. 版面：正嘜（靠左，含 2 個 Code128 條碼）與側嘜（靠右）的內容、尺寸、字型依 §3.5；支援日文與 `φ` 字型；空欄位不能讓整段消失。
4. 依紙箱規格計算每一面的起印位置與正嘜/側嘜間隙；表面與裏面方向相反；表面/裏面終了不可大於 L+W，否則要提示。
5. 雙螢幕：主畫面與大字「已噴箱數 / 總箱數」視窗分開顯示；視窗位置要記憶。
6. 狀態與告警：連線狀態、墨量低、墨水用完、卡匣異常、斷線，都要用大字視窗加聲音提示，並自動停止噴印。
7. 權限：作業員不能進入資料管理與設定；工程參數（延遲、DPI、緩衝）只開放給工程人員。
8. 只能開一個實例；噴印中鎖住會影響資料的操作；系統可備份與還原（含模板）。

### 6.2 架構上要改掉的（教訓）

1. **以「頁（箱）」為單位做閉環**：每箱分配不可重複的 page SN，同時綁定箱數、機番與兩面內容。從 X1 的回報取得「已噴頁序」（舊系統用 `imGetPrinttedPagesn`），只用確認噴出的頁序推進計數與寫入明細；停機時把「已送出但沒噴」的頁明確作廢或重排，不能讓操作員手改箱號造成落差。
2. **計數要具備併發安全**：送印與回報如果分成不同執行緒，計數要用原子操作或單一執行緒的狀態機（#25 的教訓）。`01_X1_protocol.md` 已指出 SDK 的一問一答佇列沒有逾時，一個回應遺失就會整串卡住，所以要自己加逾時與重送機制。
3. **兩面一致性**：表面（噴頭 1、2）與裏面（噴頭 3、4）若由不同控制器或觸發源處理，必須比對兩側的頁序。只要不一致就立即停機，並顯示是哪一箱。建議把 Barcode 偵錯專案（讀取器比對正反面條碼）列為選配功能，至少要預留介面與紀錄欄位。
4. **觸發來源**：記錄每一側每箱的觸發事件。偵測到多觸發（例如兩次觸發間隔小於最短箱距，或誤觸電眼）時要告警。
5. **延遲與 DPI 參數**：
   - 公式要寫在程式裡並有單元測試（§3.4）。
   - 計算結果不能是負值，若為負就拒絕送出並提示（#22）。
   - 把要寫到印表機的延遲先在畫面顯示並保存歷史。
   - 「關閉噴頭延遲」等印表機端設定，不能被控制台在開印時無聲覆蓋（#36），應明確區分哪些參數由誰負責。
   - DPI 要對應同步器規格（400 DPI 同步器），換米輪或機構時要能用校正工具重算。
6. **首箱與斷線**：送資料後要等印表機回報「就緒」或「緩衝已滿」，才提示操作員放箱（取代固定的「等 N 秒」）。斷線重連後，要先重新確認佇列內容才能續印（#13、#14）。
7. **1 吋卡匣的新硬體**：舊系統的模板高度是每面 8 × 0.5 吋（2 支 PH2 疊放 = 4 吋），`SinglePrintHeadHeight=150@300dpi`。改用 X1/SPH 的 1 吋卡匣後，每面需要的卡匣數與上下排列方式、每個卡匣的 X/Y 偏移，都要重新定義。正嘜約 85 mm 高，必須放得進新的總噴印高度；側嘜大字 21 mm 也要能在單一或跨卡匣範圍內噴出且不錯位（#2、#28）。
8. **不再依賴 Printing PRO 與 ADT**：
   - 舊系統的模板合成（Temp_InSide/OutSide、AdtTemp、BMP 轉圖）與 ADT 欄位索引（KeyCode=50…Place=31）要全部改成控制台自己排版（或使用 X1 的訊息與變數機制）。
   - 側嘜「字串轉圖 + 靠右 + 超寬截斷」的行為要改成「超寬就阻擋並提示」，不能默默截斷（#9）。
9. **資料庫與匯入**：不要依賴 OLEDB Jet/ACE（#34），改用純程式庫讀 Excel。DB 欄位使用正規名稱，帳密不要以明文存放（舊的 Config.xml 與 hejian.xml 都有明文）。生產紀錄要有主表（批次）與明細表（每箱：頁序、箱數、機番、兩面確認時間、停止原因），以支援追溯與報廢比對（參考 2015 年報廢申請表）。
10. **日誌**：每箱一筆結構化日誌（送出、兩面噴出確認、異常），可直接匯出給現場與研發。舊系統常需要「遠端備份整個 SQL 回傳」才能分析。

### 6.3 待確認事項

- 新產線的噴頭數量與位置（每面幾個 1 吋卡匣、是否仍是左右兩側各一組）、觸發與編碼器配置（是否仍共用一個編碼器、每側獨立電眼）。
- 機番格式規則（年碼 + 製番數字 + 3 位箱序是否已成為標準）、逆序是否仍需要。
- CartonSize 中「開始大於終了」的紙箱（01160、01163、01172、01173）的實際語意。
- 是否要改成直接讀客戶 ERP 的「印刷明細一覧表」（含「產品編號（紙箱）」，例如 17401158），取代手工維護 PrintData。
- 條碼讀取器（正反面比對）要納入本期還是預留。
