## 1. 現況結論

| 項目 | 結論 |
|---|---|
| 現場最後使用版本 | C++Builder 6 版 `hejian` 2.1.2.6 → 20160530「改流水號判斷」版（2021 年照片仍在使用） |
| 原始碼 | 兩代都遺失。.NET 版（2013）可 100% 反編譯成可讀 C#；C++Builder 版只能還原畫面、SQL、設定、函式名稱與大部分流程（組語推讀） |
| 功能基準 | **以 C++Builder 20160530 版的行為為準**，.NET 反編譯碼當作可讀的邏輯參考（兩代架構相同） |
| 舊噴印鏈 | 控制台 → `aimdtl.dll` → 共用記憶體 → Printing PRO（ctrler.exe）→ 4 台 SP2000 + 4 支 2 吋 PH2 |
| 舊資料傳送 | ADT：每箱 1 頁、18 欄（.NET 版 23 欄含 3 張 BMP）；PC 端自己合成模板（正嘜＋側嘜 → AdtTemp.ms）、側嘜大字轉 BMP |
| 新噴印鏈 | 控制台 → **raw TCP :25001（類 Modbus，FC 固定 0x64，Anser CMD 包在 PDU 內）** → NexGen X1/SPH，1 吋卡匣 |

**重要更正**：CAh／CFh 不是 Modbus 功能碼，是包在 FC 0x64 內的 Anser 命令；封包可達 ~5 KB，**不能用 NModbus 等標準函式庫**，要自寫通訊層。

## 2. 新系統的核心設計轉變

1. **版面改在噴碼機上設計，PC 只送變數值**
   - 正嘜／側嘜的固定文字、版面、字型、兩個 Code128 條碼都做成 X1 訊息（xml），條碼與文字物件引用動態變數 String1–20。
   - PC 不再合成模板、不再轉 BMP；舊 18 欄直接對應 CFh 的 String1–18（剩 2 欄可放產品碼＋機番合成的條碼內容等）。
   - 側嘜「靠右＋超寬截斷」改成：送出前檢查長度，超過就擋下並提示（不默默截斷）。
2. **每箱變數用 CFh（產線/工位緩衝區）**，換單時 CBh 清空，CCh 讀剩餘筆數做節流（取代 ADT 的 PrintMaxMem 緩衝頁數）。
3. **以「箱」為單位閉環**：每箱分配唯一序號，綁定箱數、機番、兩面內容；**只以噴碼機回報的實際列印計數推進箱數與寫明細**。停機時「已送未噴」的箱明確作廢/重排，杜絕歷年最多的跳號、正反面機番不一致客訴。
4. **噴頭延遲／起印位置**改由 X1 的訊息或產線參數設定（若 X1 有對應命令），公式寫成可單元測試的純函式，負值拒送。

## 3. 建議架構

技術選型（建議）：**C# / .NET 8、WinForms**（與 X1 SDK、舊 .NET 版同語言，反編譯碼可直接參照；現場電腦 Windows）。

```
MITSU.sln
├─ Mitsu.Printer        X1 通訊層（自寫，不沿用 SDK 的佇列）
│    • Framing：MBAP-like 封包組/拆，處理 TCP 分包/黏包
│    • 單一 I/O 迴圈，一問一答＋每命令逾時＋重試＋自動重連
│    • 命令：43h 版本、7Fh 警報、45h 狀態、3Ah 計數、20h+203h 啟停、
│            20h+214h/24Ch 選訊息、CBh/CCh/CFh 動態變數（CAh 備用）
│    • 模擬器（假噴碼機 TCP server）供無機台開發與自動測試
├─ Mitsu.Core           領域邏輯（無 UI、無 DB，可單元測試）
│    • 工單/箱的狀態機（待送→已送→已噴確認/作廢）
│    • 機番產生（前綴＋數值、順序/逆序、保留前導 0，用字串不用 double）
│    • 18 欄組字規則（電壓＋空白×N＋頻率、Code＋3 空白＋機番…）
│    • 欄位長度驗證、起印位置/延遲計算
├─ Mitsu.Data           資料存取（參數化 SQL，Dapper）
│    • PrintData、CartonSize、ProductionBatch（主）、ProductionCarton（每箱明細）、EventLog
│    • Excel 匯入匯出：ExcelDataReader/ClosedXML，.xls/.xlsx 都支援，CASE-No 以文字保存
├─ Mitsu.App            WinForms UI
│    • 噴印控制、資料選擇（Key code 模糊查詢）、資料管理、紙箱規格、生產紀錄、
│      系統設定、工程設定（需密碼）、第二螢幕大字箱數視窗、告警（大字＋聲音＋自動停）
└─ Mitsu.Tests          Core 單元測試＋Printer 對模擬器的整合測試
```

資料庫：沿用 **SQL Server Express**（現場已有、可承接舊資料）【待確認：或改 SQLite 免安裝】。帳密改用 Windows 驗證或加密存放，不再明碼。

## 4. 每箱生產流程（新）

```
開工：connect → 43h → 7Fh 無警報 → 停線 → 214h 選訊息 → CBh 清緩衝
      → 預送 N 箱 CFh（N 由實測緩衝深度決定）→ 203h 啟動
迴圈：每 200–500 ms 讀 CCh（剩餘筆數）＋ 45h/3Ah（已噴計數）
      已噴計數增加 → 對應箱標記「已噴確認」、寫明細、推進畫面箱數/機番
      緩衝低於水位 → CFh 補下一箱
      7Fh 警報 / 斷線 / 計數異常 → 自動停線、大字告警、記錄是哪一箱
收工：達最大箱數 → 停線 → 讀最終計數 → 未噴箱作廢 → 關閉批次紀錄
```

## 5. 開發階段

| 階段 | 內容 | 產出 |
|---|---|---|
| P0 協定實機驗證 | 用通訊層＋小工具在 X1 實機確認下列【必驗】項目 | 驗證報告、修正版協定文件 |
| P1 核心 | Printer 通訊層＋模擬器、Core 狀態機/機番/組字、Data 層＋Excel | 可用模擬器跑完一張工單 |
| P2 UI | 全部畫面、權限、雙螢幕、告警 | 可操作版本 |
| P3 X1 訊息設計 | 正嘜/側嘜/條碼在 X1 上做版，對應 String1–20 | 訊息檔＋對應表 |
| P4 現場 | 舊資料轉移（PrintData/CartonSize/生產紀錄）、試產、驗收 | 安裝包、操作手冊 |

**P0【必驗】**（程式碼無法證明，只能實機確認）：
1. CFh 是否 FIFO、深度多少、滿了回什麼錯誤碼；緩衝空時印表機行為（印空白？停機？）
2. CFh 是否需在已選訊息/列印中狀態才接受；空字串代表清空還是不變
3. 訊息中物件如何引用 String1–20（含條碼物件）
4. 45h 狀態區塊長度（56 或 68）、錯誤碼 10h–14h 是十六或十進位、是否回顯 transaction id
5. 噴頭延遲／起印位置能否用命令設定（舊系統每次開印依紙箱尺寸重算 4 組延遲）

## 6. 需要你決定 / 向現場確認的事

1. **新硬體配置**：幾台 X1/SPH、每面幾個 1 吋卡匣（舊每面 4 吋高＝8×0.5 吋；正嘜約 85 mm 高）、是否仍左右兩側各一組、編碼器/電眼配置。→ 決定 PL/PS 對應與一箱要送幾次 CFh（兩側各一台時，兩台的計數要互相比對）。
2. **正嘜高度**：1 吋卡匣若放不下 85 mm 正嘜，需客戶同意改版面或增加卡匣。
3. 技術選型：C# .NET 8 WinForms ＋ SQL Server Express 是否 OK。
4. 機番格式是否固定為「2 位年碼＋製番數字＋3 位箱序」、逆序是否仍需要。
5. 條碼讀取器正反面比對（2014 年提案）本期做或預留介面。
6. 是否改直接讀客戶 ERP「印刷明細一覽表」取代手工維護 PrintData。
7. 有沒有 X1 實機或測試機可供 P0 驗證。
